# AGENTS.md

Emacs distro on [rougier/nano-emacs](https://github.com/rougier/nano-emacs), managed by straight.el. Local git repo only (syncthing path, no remote). No tests/CI/lint.

## Launch / layout
- Needs `Noto Sans Mono` system-wide.
- `init.el` — only real config: bootstraps straight.el, sets font, installs `nano`, `(require 'nano)`. Everything resolves off `user-emacs-directory` (= launch dir).
- `early-init.el` — `package-enable-at-startup nil`; package.el disabled.
- `straight/repos/` — vendored git clones of every package. `straight/build-cache.el` = straight recipe cache. `elpa/`, `eln-cache/`, `auto-save-list/` = caches/runtime; ignore unless packaging.
- Sanity check: `emacs --batch --eval '(setq user-emacs-directory "~/.emacs.d/")' -l ~/.emacs.d/init.el --eval '(message "nano=%s" (featurep (quote nano)))'`
- Testing: if `emacs` run needed, use no-window mode (`--batch` or `-nw`) so output visible to agent; never launch GUI emacs

## Gotchas
- Package versions are NOT pinned; straight pulls latest commit on bootstrap.
- First bootstrap needs network: if `straight/repos/straight.el/bootstrap.el` is absent, `install.el` is fetched from `radian-software/straight.el/develop`.
- Edits reload via `SPC f e r` (`nano/reload-init`, §22): re-runs init.el in-place, covers bindings/defuns/setq. Font/boot changes still need restart (`SPC q r`) — §2 vars are set-before-require and `(require 'nano)` is a no-op on reload.
- Font/theme tweaks must run BEFORE `(require 'nano)` or nano defaults override them.

## Quad workspace (§9c)
- `SPC l c` = new tab, four equal columns: magit A | opencode A | opencode B | magit B. Both repos are read first, so a non-repo answer or an unsplittable frame aborts before anything is created (the tab is closed again).
- Repo prompt candidates: `nano/quad-workspace--repo-paths` = `magit-repos-alist` **cdrs** (the alist is `(NAME . PATH)`; using the car resolved names against `default-directory` and failed), `project-known-project-roots`, the current buffer's `magit-toplevel`, plus a bounded scan of `nano/quad-workspace-repo-roots` (default `(("~" . 2))`). `magit-repository-directories` is nil on this box and `project-known-project-roots` stays empty until project.el is used, so without that scan the prompt offered ZERO choices. The prompt uses `require-match` nil, so any path can still be typed.
- `SPC l` is a `read-key` loop (`nano/workspace-dispatch`), NOT a prefix map — new workspace commands are new `cond` branches, not `define-key "l X"`. The hint line and the `?` legend carry the key.
- Magit placement: `magit-status-setup-buffer` always routes through `magit-display-buffer`; bind §10c's `nano/magit-desktop--display-quietly` + `magit-display-buffer-noselect t`, then `set-window-buffer`. **`(require 'magit)` must come before that `let`** — let-binding `magit-display-buffer-function` before magit's `defcustom` runs makes it lexical and magit then dies with "Defining as dynamic an already lexical var". On the first `SPC l c` of a session that would be the whole command.
- OpenCode placement: the client is async (service → create → `opencode-session-open` → `pop-to-buffer`), so there is no buffer to relocate. `display-buffer-overriding-action` is bound INSIDE the callback to a closure that `set-window-buffer`s the pane; overriding beats `display-buffer-alist`, so §6f's scratch routing cannot hijack it. `(require 'emacs-opencode)` first — `opencode--create-session` is not autoloaded.
- Limits: magit buffers are per-repository, so a repo open in another tab shares the buffer; session panes are not restored by `SPC q r` (tab + magit only, §10c).

## OpenCode (§27)
- CLI must be installed: `curl -fsSL https://opencode.ai/install | bash` (lands in `~/.opencode/bin`). `27a0` adds that dir to `exec-path`/`$PATH`, so GUI Emacs works without a login shell.
- Tree-sitter grammars `markdown` + `markdown-inline` are required for session buffers; install once with `M-x treesit-install-language-grammar` (built libs land in `~/.emacs.d/tree-sitter/`).
- State DB: `~/.local/share/opencode/opencode.db` (override root with `XDG_DATA_HOME`). `session.model` + `message.data` hold the model per session/message. Useful for checking what model a session actually ran (`sqlite3 -readonly ...`).
- **API reality (2026-11-13):** the client provides `emacs-opencode`, NEVER a bare `opencode` feature — `with-eval-after-load 'opencode` is a dead letter and everything in §27d–h is wired in ONE `with-eval-after-load 'emacs-opencode` block after 27h. Commits 27d–h of 2026-11-12 were written against the deleted v1 package (`sczi/opencode.el`) and silently did nothing; `advice-add` on a missing symbol succeeds without error in Emacs 31, so nothing fails loudly. `nano/opencode--api-check` warns if a relied-on symbol disappears (run `M-x` load + `emacs --batch ... --eval '(require (quote emacs-opencode))'` after any straight pull to see it).
- Default model (27d): new sessions start on `nano/opencode-default-model` = `opencode-go/glm-5.3-flash`. ONE advice: `opencode--create-session :around` re-implements the package's three lines and passes `:model` itself, captured **lexically in the continuation**. Keys are `providerID`/`id` (server API); the created session's model shows in the header via `opencode-session--update-session`.
- **Never thread that model through a dynamically-bound variable.** The first create of an Emacs session hits an empty agent cache, so `opencode-session--ensure-agents` answers ASYNCHRONOUSLY — after any `let`-binding around `opencode--create-session` has been unwound. The old two-advice design (dynamic `nano/opencode--inject-model` + advice on `opencode-client-session-create`) therefore injected nothing on the first session and only worked on the second; symptom was a session header with no model. Warm-cache creates hid the bug. The advice now also `advice-remove`s that stale client advice by symbol for reload safety.
- Cursor follow (27e): nothing custom. The session buffer is `text-mode` derived — there is NO comint in this package — and the renderer itself pins tail windows (`opencode-session--message-render-window-states`, `follow-bottom`). `C-c C-l` is `opencode-session-select-model`; never bind over it.
- Permission gate (27f+27h): every prompt funnels through `opencode-session--prompt-permission` (via `--defer-prompt`, a 0 s timer running the thunk inside the target session buffer, so `current-buffer` there is the prompt's home). The `:around` advice prompts when `nano/opencode--prompt-wanted-p` (selected window + no live minibuffer + no active transient), otherwise parks `(permission connection state)` in `nano/opencode--pending` and notifies via dunst once per request id (`nano/opencode--notified`). Re-offer runs from the session buffer's **buffer-local** `post-command-hook` (`nano/opencode--reoffer`, armed per buffer by `opencode-session-mode-hook` + `--permission-arm-all`) — a global `add-hook` there lands in one startup buffer and never reaches session buffers. Cleanup rides `opencode-session--remove-prompt :after`; notified ids clear once nothing is parked. `C-g` at the prompt DENIES (the package replies "reject" on quit) — a request is recoverable only while parked. Notification transport: dunst on the session bus (`org.freedesktop.Notifications`); `notifications-notify` with actions; this dunstrc maps `mouse_middle_click = do_action`, so the click action needs a MIDDLE click. No daemon → echo-area fallback.
- Finish notice (27g): `opencode-session--handle-execution-ended :after` (`session.execution.succeeded|failed|interrupted` — there is NO `session.idle` and no `opencode--handle-message` in v2). Skips interrupts, subagents (`opencode-session--subagent-parents`), sessions without a live buffer, and sessions whose buffer IS the selected window (watching the reply is the point; dunst is for when it is not). Title from the buffer's `opencode-session--session`; failed turns use critical urgency.

## Session minimap (§27i)
- `SPC a c l` = `nano/opencode-minimap`: read-only `*OpenCode Roster*`, one line per **open** session, refreshed every `nano/opencode-minimap-interval` (5 s) while the window is visible. `RET` opens the session by id, `g` re-polls.
- **Scope: sessions with a live Emacs buffer only.** `nano/opencode-minimap--open-p` checks the package registry `opencode-session--buffers` for a `buffer-live-p` buffer, and `--on-sessions` `seq-filter`s with it. The roster is a window switcher for this Emacs, not a server inventory — CLI/other-editor sessions stay out, and killing a session buffer drops its row on the next poll (state is still polled from the server, so a visible-but-unselected buffer shows the truth).
- **Layout: exactly three fields — status, name, directory — capped at `nano/opencode-minimap-width` (80) columns.** Status is fixed 3 (`nano/opencode-minimap-state-width`), name fixed 38 (`nano/opencode-minimap-name-width`), and the directory absorbs the remainder via `nano/opencode-minimap--directory-width`, so the cap holds at any width setting. Fields go through `--field` (`truncate-string-to-width` + pad, "..." suffix) and the line is `string-trim-right`ed, so no row carries trailing whitespace. Measured with `string-width`, not `length` — CJK titles are 2 columns per char. The agent column was dropped by request; there is no AGENT field any more.
- Three states, most urgent first: `!!` needs you (pending permission), spinner working (running execution), `.` idle. ASCII marks for needs-you and idle; the busy mark is the first frame of `nano/opencode-minimap-spin-frames`. Emoji and geometric glyphs (`●`, `▶`) stay out — `fc-match` on the devbox resolves even "DejaVu Sans Mono" to Adwaita Mono. The face carries the colour; the characters carry the state.
- **No legend, no header row.** The roster is a bare list; the faces and the moving spinner carry the meaning. Removing them also removed the only two uses of a bar face, so every row is plain buffer text.
- **Colours come from BUFFER faces, never `nano-face-header-*`.** Those are modeline blocks: `nano-face-header-faded` is hardcoded `#fbf8ef` on `#7e7482`, which painted every row near-white on dark grey — the bug this section used to have. `nano/opencode-minimap-waiting` inherits `nano-face-popout`, `-busy` inherits `nano-face-salient`, `-idle` and `-name` inherit `nano-face-faded`, so the roster follows the live theme and `SPC t n` recolours it. Do not inherit `error` either: §7c remaps it to `nano-face-critical`, a solid red block (fg `#50425c` on bg `#e0211d`).
- The row button spans the text only. `make-text-button` is called with an explicit `(goto-char start)` + `line-end-position`, because after the row's `"\n"` is inserted the plain `line-end-position` returns the empty NEXT line and the `button` face (inherits `link`: blue + underline) paints a stray cell at the end of every row.
- Status is POLLED, not pushed, so the roster works for sessions with no buffer: `GET /api/session/active` (map sessionID -> `{type:"running"}`) for working, `GET /api/permission/request` for needs-you. The latter is **location-scoped**, so it is fetched once per distinct session directory and merged — one call only ever sees one project.
- **Requires OpenCode 2.x.** On 1.x `/api/session/active` is always `{}`, so every session would read idle; `nano/opencode-minimap--check` warns in the echo area instead of lying. Upgrade with `opencode upgrade --major`.
- The spinner animates by `subst-char-in-region` over one character per running row, addressed by a marker in each buffer's `nano/opencode-minimap--marks`, so text properties, buttons and point survive and nothing re-lays out. Frames are `- \ | /` (all one char wide, hence subst rather than re-render). The tick costs one `get-buffer-window` when the roster is hidden.
- Verified live in `tmux` (100x24, real TTY): frames advance `-` -> `\` -> `|` -> `/`, and `capture-pane -e` shows the intended colours with the theme background, no hardcoded bar background.
- `--marks` is **buffer-local** and rebuilt by every redraw; write it and read it inside the roster buffer only.
- Redraw preserves point: if point was on a session row it is restored to the same session, so the 5 s poll and the spinner never yank the cursor.
- The `-`/spinner is invisible in a chat transcript or a saved buffer dump — it only moves in a live window. To see it: open the roster, or `sit-for` with the buffer in a window (batch `--eval` timers do fire this way).

## Ghostel (§30)
- `SPC a t g` = `ghostel` (libghostty-vt terminal, `dakra/ghostel` from MELPA via straight). Separate from the §29 builtins; both exist side by side.
- Native module lives at `var/ghostel/ghostel-module.so` + `ghostel-module.version`, set by `ghostel-module-directory`. Deliberately outside `straight/` — straight replaces package dirs on rebuild, and re-mapping a live `.so` under a running Emacs breaks its mmap.
- Install/refresh by hand: download `ghostel-module-x86_64-linux.so` from the GitHub release into that dir and write the matching version to `ghostel-module.version`. `M-x ghostel-download-module` does the same in-process; `M-x ghostel-module-compile` needs zig 0.17.x.
- The loader refuses to map a module whose sidecar version is below `ghostel--minimum-module-version` (Elisp side), so a version bump in the package needs a matching module refresh — symptom is "Module version X on disk is older than required Y".
- Starts in evil insert state (like §29 shells). Shell integration (OSC 7 directory tracking, OSC 133 prompt nav) is injected for bash/zsh/fish automatically, no rc edits.
- `evil-ghostel` (same repo, MELPA) is available but not installed; it maps vim operators onto the PTY.

## Matrix chat (§31)
- `SPC a m` = ement.el (`alphapapa/ement.el`, GNU ELPA via straight's gnu-elpa-mirror clone). Keys: `c` connect / `x` disconnect / `k` kill buffers / `l` room list / `v` view room / `j` join / `d` direct message / `p` directory / `s` directory search / `m` mentions / `n` notifications.
- ement is lazy: `straight-use-package` only registers the recipe. Only `ement-connect`, `ement-room-list`, `ement-directory` carry autoload cookies; the rest (`ement-view-room`, `ement-room-join`, `ement-send-direct-message`, `ement-notify-switch-to-*`) do NOT. Each key therefore goes through a `nano/ement-command` wrapper (macro in §31) that `require`s the owning feature then `call-interactively`s the real command — binding the raw symbol would be void-function until something else loaded ement, and a lambda would lose which-key/`describe-key` names.
- No E2EE. Encrypted rooms are unreadable without a proxy: `bhwdev/ement-e2ee` (matrix-sdk-crypto/vodozemac, prebuilt binaries) or Pantalaimon (archived 2025-06, libolm). Neither is installed.
- **SPC is the leader inside room buffers.** ement binds `SPC` to `ement-room-scroll-up-mark-read` in `ement-room-mode-map`, but the evil normal-state map shadows it, so `SPC` opens the leader. Scroll with `C-d`/`C-u` or `S-SPC`; `?` (or `<`) opens ement's transient menu.
- Evil integration is evil-collection's `modes/ement/` (already vendored). Two things are required and easy to lose: (1) `ement` must be in `evil-collection-mode-list` — §31 `add-to-list`s it; (2) ement's modes derive from `fundamental-mode`/`magit-section-mode`, so they land in emacs state unless seeded — §31 `evil-set-initial-state`s all five to `normal` at init.
- §10's `nano/evil-collection-ensure` only triggers on magit/elfeed load, so §31 adds its own `(with-eval-after-load 'ement (nano/evil-collection-ensure))`. Calling it twice is a no-op guard on `nano/evil-collection-initialized`.
- First `SPC a m c` clones and builds ement plus `map`, `persist`, `taxy`, `taxy-magit-section`, `svg-lib` (~30s, needs network). `plz` and `transient` were already built for other packages.
- **Login persists via the access token, never the password.** `ement-save-sessions` is `t` and `ement-sessions-file` is `var/ement/sessions.el` (dir created 0700; ement chmods the file 0600). On quit/restart `ement--kill-emacs-hook` writes user id + homeserver + device id + **access token**; `ement-connect` reads it back and resumes syncing with no prompt. The password is fed from `read-passwd` straight into the login request and is never written. A token is a per-device key — revoke it server-side (Element → Settings → Sessions) and the next sync fails with `M_UNKNOWN_TOKEN`; the stale session is NOT auto-cleared, so re-login with `C-u SPC a m c` (prefix = fresh login). `nano/ement-command` passes `current-prefix-arg` through, verified.
- **Two traps that silently cost you the session.** (1) `ement-save-sessions` has a `:set` that installs `ement--kill-emacs-hook`; a plain `setq` sets the value and never installs the hook, while `customize-set-variable` run BEFORE ement loads finds no `:set` property and silently degrades to a plain set. §31 therefore sets the value with `setq` and adds the hook explicitly under `with-eval-after-load 'ement`. (2) `ement--write-sessions` uses `with-temp-file` inside an `ignore-errors` hook, so a missing parent directory fails silently — hence the `make-directory` at init.
- `restart-emacs` (built in, `files.el`) is `(save-buffers-kill-emacs nil t)`, so `SPC q r` runs `kill-emacs-hook` exactly like `SPC q q`; both persist the session.
- Room list / directory / describe buffers are `magit-section`-derived, so §10c/§6 window routing and the magit `M-0..M-9` winum rebind matter there too.

## Session restore (§5d + §10c)
- `SPC q q` / `SPC q r` save to `var/desktop/.emacs.desktop`: every tab (workspace) with its name, each tab's window layout, every file buffer, and — since §10c — every magit buffer. `tab-bar` must be on before `desktop-save-mode` reads, else framesets come back without tabs.
- `desktop-load-locked-desktop` is `'check-pid`, not nil: a lock left by a crash/kill is ignored once that PID is gone, while a live second Emacs still refuses. With nil, one crash silently emptied the next session ("Desktop file in use; not loaded").
- **The restored agenda keeps its VIEW.** `*Org Agenda*` is one buffer name shared by every org agenda view, so the name says nothing about which view was on screen, and the handler used to call `org-agenda-list` unconditionally — every restart turned a TODO list back into the weekly agenda. `desktop-save-buffer` is now the function `nano/org-agenda--desktop-save`, whose return value desktop hands back as MISC; it records `org-agenda-type`. `nano/desktop-restore-org-agenda` replays `org-todo-list` for `todo` and `org-agenda-list` for `agenda` and for anything unknown (tags/search views, and desktops written before this existed), so old desktop files still restore.
- `org-agenda-type` is NOT trustworthy when `org-agenda-mode-hook` runs — `org-agenda-mode` runs the hook before the view is inserted, so it is still nil there. Every agenda line carries the kind as an `org-agenda-type` text property instead; `nano/org-agenda--current-type` reads that at SAVE time, when the view is definitely on screen. Do not move the detection into the mode hook.
- Magit buffers visit no file, so `desktop-save` never saved them; the frameset then pointed at buffers that were never recreated and `tab-bar` substituted ` *Old buffer magit: …*`. §10c adds the `desktop-save-buffer` + `desktop-buffer-mode-handlers` pair. Rebuild goes through magit's own `*-setup-buffer` functions — the refresh path alone fails without the mode setup (e.g. `magit-log-margin` is unbound, `wrong-type-argument number-or-marker-p`).
- Handlers are registered at init (`with-eval-after-load 'desktop`), **not** from `magit-mode-hook`/`with-eval-after-load 'magit`: `desktop-read` runs from `after-init-hook` before magit loads, and `desktop-load-file` loads magit only when it reaches the first magit entry — after that entry's handler lookup. Registering late drops exactly one magit buffer per session ("1 failed to restore").
- A magit buffer whose repository directory is gone is skipped (nil from the handler, placeholder shown); binding a nonexistent `default-directory` would signal and abort the whole restore.

## Roam completion DWIM (21d)
- `, r f` / `org-roam-node-find` prompts run through fido-vertical with custom RET/TAB/nav semantics (Spacemacs/vertico contract):
  - The candidate list is a PASSIVE menu. The first entry being highlighted is a "ghost" — plain RET submits the TYPED literal (creates a new node, or opens an exact-title match). It does NOT coerce to the highlighted candidate.
  - Navigation (C-j/C-k, C-n/C-p, arrows, M-</M->) actively selects: each press rotates `completion-all-sorted-completions` from the TOP (stateless rebuild in `nano/org-roam--fido-nav`/`-nav-back`, :override advice on `icomplete-forward/backward-completions`), and sets buffer-local `nano/org-roam--fido-navigated`.
  - RET after navigation force-completes the focused candidate (`icomplete-force-complete-and-exit`), then clears the flag.
  - TAB (`nano/icomplete-fido-tab-dwim`) fills the input with the focused candidate (`minibuffer-force-complete`) — vertico `vertico-insert` parity: after TAB the filled text IS the input, so the next RET submits it. Non-roam prompts: stock `minibuffer-complete`.
  - C-M-j keeps stock force-select-first. Non-roam prompts: RET/TAB fall back to stock `icomplete-fido-ret`/`minibuffer-complete` (DWIM delegates).
- Why :override on the icomplete nav commands instead of :after: stock icomplete auto-focuses entry 1 on every refilter; the movers must ignore the stale rotation and always step from the fresh top (vertico behaviour).
- The completion cache is DOTTED on fresh computation (`completion--cache-all-sorted-completions` stores `(nconc all base-size)`: `(c1 c2 . 0)`, a single candidate is `(c1 . 0)`). `nano/org-roam--fido-proper` walks cons cells only to strip that atom — `mapcar`/`butlast`/`nconc` on the dotted tail signal wrong-type-argument listp 0 (the first C-n used to die with [Wrong type argument: consp, 0] and leave the ghost unselected).
- nav-back guards the single-candidate case (no rotation, no list duplication) and conses `(car (last comps))` onto `(butlast comps)` — consing onto the full list duplicated the tail into the cache.
- Plain RET is `exit-minibuffer`, NOT `minibuffer-complete-and-exit`: the latter expands a novel prefix to the first flex match on first RET (forces an existing node), defeating new-node creation.

- **Never put a "call the stock command" fallback inside an `:override` advice.** §21d hooks the roam mover onto `icomplete-forward-completions` / `-backward-completions`, which are what `C-n`/`C-p` and `<down>`/`<up>` are bound to in `icomplete-vertical-mode-minibuffer-map` — so they run in EVERY prompt, not just roam. An `:override` whose non-roam branch calls `icomplete-forward-completions` calls the advice itself, and the first up/down in any file/choice prompt dies with `(excessive-lisp-nesting 1601)`. It must be `:around` (`(orig &rest args)` → `(apply orig args)` for non-roam), which cannot re-enter. Both advices carry a `(name . …)` property so a `SPC f e r` reload replaces rather than stacks them.
- `M-<`/`M->` (`icomplete-vertical-goto-first`/`-last`) are deliberately NOT advised. Their stock bodies are `(while (icomplete-backward-completions))` and only terminate because `icomplete-scroll` is non-nil; this config leaves `icomplete-scroll` nil, so stock correctly signals "Only works with `icomplete-scroll'". A rotation-based replacement cannot know when it has reached the first entry and would spin forever.
- Reproducing completion bugs needs a real TTY: `emacs --batch` cannot service a minibuffer (`end-of-file "Error reading from stdin"`), and `ssh` without `-tt` leaves `emacs -nw` without a terminal, so the run silently produces nothing and a stale output file looks like a pass. Use `ssh -tt … emacs -nw -l init.el -l script.el` with results written to a file (the minibuffer overwrites the echo area), feeding keys via `run-with-timer` + `execute-kbd-macro`.

## Leader key bindings (§4a)
- Bind with `nano/leader-keys`, not raw `define-key`. One form per key, label inline:
  `(nano/leader-keys ("a m c" 'nano/ement-connect "connect"))`. It emits the `define-key` **and** the `which-key-add-key-based-replacements` entry from the same triple, so the key string appears once instead of three times (key / `"SPC key"` / regex). Before this the file had ~140 leader keys, each duplicated into a hand-written `"SPC …"` label cell — the largest duplication axis and a silent desync if either copy drifted.
- `("key" nil "label")` = label-only group heading (no command bound); `("key" 'cmd nil)` = bind with no label, which keeps which-key's command-name fallback. Both are used deliberately; do not "fix" them.
- The macro is idempotent under `SPC f e r` — `define-key` overwrites, and repeated loads leave the same 22 top-level prefix keys.
- Bindings live with the feature that owns them, not in §5. §5 holds only cross-cutting keys (file/buffer/window/quit). Feature keys belong next to their implementation (opencode §27, elfeed §23, roam §21, ement §31, …).

## Workflow
- Add a package: add `(straight-use-package '(pkg :type git :host github :repo "user/pkg"))` + `(require 'pkg)` in `init.el`.
- Edited a vendored package under `straight/repos/`? `M-x straight-rebuild-package RET <pkg>`, or `M-x straight-pull-all` to sync upstream.

## Principles
- Performance first. New features -> lightest solution wins. Prefer built-ins / minimal deps, lazy-load, fast startup. Justify heavy packages.
- When design new UX/UI or behavior where there is no reference to emulate, employ design principles found in `./DESIGN.md`.

## UX/UI Reference
- Future features needing UX/UI design — learn from Spacemacs as primary reference (mnemonic SPC leader, which-key, transient states, layer organization).

- This repo currently minimal (`init.el` already seeds `spacemacs-leader-map` + `which-key`); future builds extend that pattern while staying light.
